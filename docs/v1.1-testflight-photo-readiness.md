# v1.1 TestFlight photo readiness — 2026-10-14

## Changes in this task

- Native pending photos now save `loads-photo:v1/post-photos/<owner>/<client-post-id>.jpg`, resolved against current `Paths.document` when uploading.
- Existing absolute file URIs ending in the exact owner/post photo path are read from the current container. Supports iOS Documents and Android files roots. Stored snapshots are not migrated or rewritten.
- Upload passes the owner and client post ID to the resolver. Other owners/posts, unsupported versions and unsafe path segments fail before upload. No old absolute path is read as a fallback.
- Missing/unreadable photos fail only that send attempt. The existing failed snapshot is retained. Existing server-success lookup and deletion tombstone lookup still run before photo reads. Immutable upload paths and `upsert: false` remain unchanged.
- Existing files are not deleted, moved or overwritten by this change. Explicit account deletion behavior is unchanged. Web continues using persisted JPEG data URLs.
- `app.json` display version is 1.1.0. `eas.json` remains remote version source / production autoIncrement / production environment / store distribution. Existing local buildNumber 1 was not changed; remote numbering is authoritative when initialized, and its actual current value must be checked before building.
- `.gitignore` now excludes root tmp/, output/ and coverage/. No .easignore exists, so EAS uses .gitignore. Required source/config/lockfile/icon paths remain included; environment and credential exclusions remain intact.
