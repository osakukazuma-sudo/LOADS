# Architecture Notes

2026-10-06。実装を変更せず、現状の責務と将来の分割候補を記録する。

## Workout screen

`src/app/workout.tsx`は5,327行、113,101 bytes。この確認時点の値であり、今回の整備では編集しない。

| 現在の責務 | 将来の分割候補 |
| --- | --- |
| セッション開始・復元・経過時間・保存・終了 | セッションhook。ユーザー別保存と終了順序を維持 |
| 前回の同じfocusの記録、トップセット、重量／回数／volume PR | 純粋な計算関数。Strength/Cardio判別と完了set条件を固定 |
| 種目追加・focus選択・並替え・セット編集・メモ | 種目／セットUIと編集操作。入力途中の文字列を保持 |
| テンプレート保存・開始・削除 | 専用UIと操作hook。重量・回数を引き継がない契約を維持 |
| JSX・モーダル・styles | 画面部品。計算と保存の契約をテストしてから段階的に分離 |

Cardio表示、種目ライブラリ、端末保存、通知同期などは既に画面外に存在する。今回の目的は公開用説明の整備であり、画面分割・ルーティング変更・依存更新は実施しない。

## Persistence boundaries

- ワークアウト、active workout、テンプレートはUUID別のAsyncStorage。
- 投稿はoutboxのsnapshotから送信し、client IDとDB制約で再送を収束させる。
- Authセッションは端末に永続化。非同期処理中も所有者変更を検査する。
- 写真は非公開Storage。清掃・アカウント削除はFunctionsとworkerを使う。
- 通知同期は保存とは別経路。通知失敗で端末の記録を失わない。

## Verification boundaries

ローカルテスト、ブラウザーでの本番API確認、実機操作は異なる証拠として扱う。2026-10-05の審査準備では専用アカウントのブラウザーログイン、記録、履歴、テンプレート保存、投稿、検索を確認した。iOS build 7のカメラ／APNs等の保証ではない。
